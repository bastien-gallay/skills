# wrap configuration — truepath

## Canonical locations

- index: `README.md`, *What it covers* must match what `SKILL.md` documents
- entry point: `README.md`, `## Status` (version, date, published or not)
- lessons: this repo *is* a skill; a rule goes in `skills/truepath/SKILL.md`,
  a limit under its *Limits*
- decisions: no ADR directory. `CHANGELOG.md`, one entry per version
- journal: none
- tracker: `registry.json` at the root of the monorepo carries the version;
  a release is followed by a pull request that updates it

## Verification commands

- blocking: `markdownlint-cli2 README.md CHANGELOG.md .wrap.md "docs/*.md" "skills/truepath/**/*.md"`
  — CI pins version 0.24.0
- blocking: `jq -e . .claude-plugin/plugin.json ../../.claude-plugin/marketplace.json`
  — `plugin.json` carries the version, matched by `CHANGELOG.md`; the root
  marketplace lists truepath without one
- blocking: `python3 -m unittest discover -s tests` — every check bites, the
  port examples rebuild byte for byte into their committed `sim.html`, the
  oracle example exports its committed `cases.json`, the built pages play
  through
- blocking: `uvx ruff@0.17.5 check skills tests` — rules in `ruff.toml`;
  `ruff format` is not used
- the same four run in the monorepo's `.github/workflows/truepath.yml` on
  every push to `main` and every pull request touching `plugins/truepath/`,
  the tests on Python 3.9 and 3.13 through `uv`; it also refuses a
  `plugin.json` and changelog that disagree on the version, or a root
  marketplace entry that carries one
- a release follows `docs/RELEASING.md`

## Disposable zones

- `.truepath/`, `__pycache__/`, `.ruff_cache/`, `.claude/` — gitignored build
  and tooling state; they come back, ignore them rather than delete them

## Commit conventions

- format: `truepath <version>: <the conclusion>`, GPG-signed
- push: a branch and a pull request on the monorepo, never `main` directly
  (a convention: `main` has no branch protection)
  (superseded 2026-11-23: "`main` only" dates from truepath's own
  repository, before the monorepo)

## Notes

- Examples are neutral and self-contained: no name, data or case from a real
  project goes into a spec committed here.
- After a change to `runtime.html` or `layout.py`, rebuild the four port
  examples (`refund-window`, `free-shipping`, `deploy-job`, `canyon-chase`)
  and commit their `sim.html` with it; retake
  `docs/refund-window.png` (pair tab, last step, 1280×800 at 2×) and
  `docs/free-shipping.gif` (matrix for 2 s, a click on the `≠` cell of Q1,
  the case played to its end; 1100×700, 12 frames a second, 64 colours)
  and `docs/canyon-chase.gif` (*The canyon* race from Play to its end,
  1100×700, 10 frames a second, 64 colours, no dither: the camera moves,
  so every frame changes) when the look changes.
- A change to the page's look is tried first on a built page: a script of
  exact replacements (each must match once) patches one example's
  `sim.html`, checked in a browser; the same script then patches
  `runtime.html`, and the rebuilt example must equal the patched one byte
  for byte. 0.4.0's case head went this way.
- A change to how the page moves (camera, pace, arrivals) is checked in a
  browser, frame by frame, before it ships: the share of frames each dot
  stays in view, how often the zoom turns round, the dot's speed per frame.
  The Node player in `tests/` has no layout and sees no camera; 0.3.1
  passed every test and still lost the fastest dot of a race on arrival,
  and its zoom breathed with each pass of a loop (fixed in 0.3.2).
- `CHANGELOG.md` takes no *Unreleased* section: CI compares its first
  heading with the version of the manifests. Work between two releases goes
  under the current version, marked as after the tag, or under the next one.
- Work marked *after the tag* reaches no installed user: Claude Code reads
  `plugin.json` to decide an update. When a user waits on a fix, cut the
  release (patch, unless a spec stops building) rather than leaving it
  after the tag; 0.1.2 was cut for a user still on 0.1.1.
- The changelog, release notes and issue comments are public: no
  colleague, employer or real case in them, as for the examples, nor in
  this file. The 0.1.2 entry first named who had used it.
- In a Claude Code sandbox, `uvx ruff` and `gh` fail and a signed commit
  cannot be made: `uv` panics there before `ruff` starts. That is the
  sandbox, not the code; `uv run --no-project python -m unittest` works.
